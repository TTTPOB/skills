# 样式与写作偏好

使用者对学术汇报的固定偏好。工具和流程见 [SKILL.md](SKILL.md)。项目自己有绘图或报告规范时，以项目规范为准。

## 1. 版式

- 画布 1280×720，根字号约 28px，正文左对齐。
- 正文字号不低于约 20px；脚注不低于约 13px。
- 每页一个要点；内容相近的两页合并成一页。
- 脚注（来源、引用）统一绝对定位贴页面底边，不跟在最后一个元素后面。
- 图等比缩放（`max-height` + `object-fit: contain`），按整页宽图、双栏图、示意图分几个固定尺寸类。
- 表格用独立的字号类，不靠全局缩放。
- 关闭切页动画。

## 2. 配色与图

- 白底、扁平、装饰克制，注意力放在数据上。
- 分类色：蓝 `#4C72B0`、红 `#C44E52`、绿 `#55A868`、紫 `#8172B3`、灰 `#8C8C8C`；正文深蓝灰 `#20344A`，次要文字 `#526171`。
- 带生物学或实验语义的颜色（如某个荧光蛋白、某一侧构建）优先于调色板顺序，全稿同一对象同一颜色。
- 中文字体用无衬线（Noto Sans CJK SC 一类）。
- 原图从源文件（原始图片、旧 pptx 的 media、绘图脚本输出）直接取，不截图、不做有损二次转码；矢量图保持矢量。
- 已有的精细示意图优先复用；新画的示意图要和已有图同一风格、同一精细程度。
- 用户指定用某张已有图时，就用那张，不自行重画替代。

## 3. 公式

- 页面公式用 MathJax CHTML，不用 Unicode 字符拼公式。
- 示意图里的公式用 MathJax 渲染成 SVG 后合进图里，与图形对齐。

## 4. 写作

1. 学术语体，陈述直接；不夸张，不用营销式表述。
2. 不给每句话挂免责声明（"仅供参考""尚未验证""不代表……"）；真正改变结论的限定集中写在一处。
3. 投影上不出现代码变量名、脚本名、文件路径，也不出现过程性词语（"本轮""修订后""v2""本项目"）。
4. 不提读者没见过的材料（"旧稿第 8 页""上次讨论"），不用没有交代过的指代（"该定义""上述标准"）。
5. 术语全稿统一，包括大小写和空格；有术语表时与术语表一致。
6. 面向非本领域听众时，先讲为什么重要（背景、rationale），再讲方法和结果。背景和论证沿用用户已有的旧稿和原论证，不用泛泛的通用背景代替。
7. 引用遵循学术规范：作者、标题或期刊、年份，附 DOI 或链接；图注写清图出自哪篇文献的哪张图。较多时末尾加参考文献页。
8. 脚注只放来源和引用；制作过程、处理细节不写进脚注，也不写进讲者备注。
9. 进度汇报：先按时间线列已完成的事，再按研究线列后续安排。

## 5. 修改方式

- 只改用户这次指出的范围；用户举的例子代表一类问题，要全稿排查同类问题。
- 改完渲染一次就交付，不反复验证；用户明确要求检查时再做第 9 节的检查。

## 6. 交付前自检

- [ ] 术语全稿一致，无代码名、过程词、无指代的表述
- [ ] 无逐句免责声明，无夸张用词
- [ ] 脚注贴底，只有来源和规范引用
- [ ] 公式正常渲染，无 Unicode 拼写的公式
- [ ] 图为原图、清晰、等比
- [ ] 交互功能所需文件都在本地
